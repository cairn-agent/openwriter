## Blog post

This document is a blog post: content_type "blog", metadata blogContext. The editor shows the post as it will read: cover, title, description (counted against 160 characters), then the body, with a Metadata panel holding date, author, slug, tags and draft. post_to_blog publishes it to a GitHub blog repo; publish_to_site publishes it to an OpenWriter site.

**The document title is the post title.** post_to_blog writes it into the post's frontmatter and ignores blogContext.title, so the title is set with create_document's title or rename_item. A rename_item from an agent stays pending until the writer accepts it, and until then post_to_blog publishes the old title. A post created without a title is called "Blog Post", which is never replaced automatically. The site prints the title above the post, so the body never opens with it: a body starting "# <title>" shows it twice.

**blogContext holds the post's own fields.** What post_to_blog puts in the frontmatter: description, date (YYYY-MM-DD; today, in UTC, when missing), author, tags, category, slug, draft, subtitle, excerpt, coverImageAlt and coverImage. Every other key (active, lastPublish, coverImages, title, anything else) and all top-level metadata stay out. Fields every post on a site shares, such as layout or the default author, belong to the site (add_blog_site, edit_blog_site frontmatter_defaults), not to one post. set_metadata({ docId, metadata: { blogContext: { description } } }) merges into blogContext one level deep: the keys not named, lastPublish among them, stay.

**The slug** is the post's file name and URL: lowercase words joined by hyphens. post_to_blog takes its slug argument, else blogContext.slug, else the title made into a slug. The editor saves a slug made from the title, and today's date, the first time a writer edits its description, date, author or slug field, and blogContext.slug wins from then on, so a post still titled "Blog Post" at that moment keeps the slug "blog-post" until blogContext.slug is set. Publishing the same slug again overwrites that post; publishing under a new slug leaves the old file in the repo.

**The cover** is blogContext.coverImage, a path under /_images/, with its alt text in blogContext.coverImageAlt. insert_image({ prompt, aspect_ratio }) with neither docId nor set_cover generates a picture and returns its path ("/_images/<name>.png") without placing it; set_metadata({ docId, metadata: { blogContext: { coverImage, coverImageAlt } } }) makes it the cover, written at once with no review. insert_image's set_cover writes articleContext, the X Article cover, which post_to_blog never reads. A cover that is not a /_images/ path publishes as a frontmatter path to a file that was never copied. post_to_blog copies the cover into the site's image folder renamed by the site's image naming (og-<slug> by default) and copies each body image under its own name.

**post_to_blog({ site_id, slug, commit_message })** publishes the document open in the editor; it takes no docId. It needs a site registered with add_blog_site (list_blog_sites shows them; inspect_blog_repo proposes a new site's settings from its existing posts), a title, content_type "blog", and GitHub CLI sign-in. It refuses frontmatter the site's Astro content schema rejects, listing the issues. On success it records blogContext.lastPublish { publishedAt, publishedUrl, commit, file } and returns the live URL when the site has a site_url. It has no publish time: the editor's Schedule button and schedule_post do not schedule a GitHub post. publish_to_site({ publish_at }) schedules a post on an OpenWriter site, using blogContext.coverImage as the cover when no cover_url is passed.

**One document is one post.** Another version is a new blog document, so the earlier draft stays to compare.
